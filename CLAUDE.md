# Retrolash: project context

Quiplash-style party game for Scrum retrospectives. The big meeting-room screen is the host; players join on phones via QR code or a 4-letter room code. See README.md for gameplay and commands.

## Stack
- React 18 + Vite 8 + TypeScript (client, `src/`)
- Node game server: `server/game.ts` is the **server-authoritative** state machine (one `GameRoom` per game, transport-agnostic); `server/main.ts` is the runtime (static `dist/`, WebSockets on `/parties/main/<room>?_pk=<id>`, state saved as JSON in `DATA_DIR`). Single instance by design.
- Client uses `partysocket` purely as a reconnecting WebSocket; there is no PartyKit dependency any more
- `shared/`: wire protocol types (`types.ts`), screen texts in English + Swedish (`i18n.ts`, `Strings` type keeps them in sync), prompts (`prompts.ts` English + Sprint packs, `prompts-sv.ts` Swedish), used by both sides. Client reads strings via `useT()` in `src/lang.tsx`
- No router. Query-string routes: `/?host=ABCD` (big screen), `/?room=ABCD` (phone)
- Deploy target: Azure Container Apps (consumption, scale to zero, max 1 replica) on the user's Visual Studio/MSDN subscription, image on `ghcr.io/flowersfx/retrolash`. See `infra/README.md`. Always pass `--subscription` explicitly: the user's az default is an unrelated subscription
- Repo: https://github.com/flowersfx/retrolash (public). CI: `.github/workflows/deploy.yml`

## Design decisions (agreed with the user)
- Round order (`planRounds` in `shared/types.ts`): **Check-in** (anonymous sprint weather) → **Did we do it?** (only if last retro's action items are pasted in the lobby) → **Warm-up** (pure-fun jokes) → **Emoji Only** → **The Sprint** (retro prompts from a chosen pack: classic mix, Start/Stop/Continue, 4Ls, Sailboat, Mad/Sad/Glad; head-to-head; at least 2 rounds, 3 with 3 players; later rounds score ×3) → **Kudos** (anonymous shout-outs to a teammate or the team, no score) → **Last Lash** (one prompt, multi-vote, ranked action items, people volunteer as owners) → **Podium** (auto, skipped in anonymous mode) → summary.
- Each head-to-head matchup has a server phase `matchupIntro` (3.6 s anticipation) before `voting`. The host lags its stage behind the live view by 650 ms on screen changes so the old screen can animate out (`useStaged` in `src/Host.tsx`); card exits are 5 CSS variants picked per matchup. A unanimous win (RETROLASH) knocks the loser out and centres the winner.
- Everything auto-advances on timers (the Sprint discussion pause defaults to 60 s, P holds it). Only Last Lash results and the summary wait for the facilitator. "Wait for me" (discussionSeconds 0) restores manual Sprint pauses.
- **Audience** role (`audience` flag on the player): votes, reacts, can own action items; never answers, scores, does the check-in, or blocks auto-advance (gets a 5 s grace after players finish voting). Max 40, separate from the 16-player cap.
- Big screen should feel like a show: matchup intros, voters' coloured name plates fly (FLIP) from a pool onto the card they picked, count-ups, streak/comeback/lead-change callouts, confetti, synthesized Web Audio sfx + background music loop (`src/sound.ts`, host only, music ducks under sfx and quietens during discussions; 🎵 panel has music on/off + music/effects volume, stored in localStorage), floating emoji reactions, commentary lines, a mini QR in the header mid-game. Respect `prefers-reduced-motion`.
- Players choose avatar (unique among players) and plate colour (`PLATE_COLORS`). A **VIP** flag (set by the host, 🎛️ in the lobby) makes a phone a remote: start/next/hold. Phones see their own matchup result (`myResult`) and rank, held back for `resultInMs` until the big screen has counted the votes in (`revealTiming`).
- Spoken prompts (`server/tts.ts`): Azure AI Speech REST, generated on demand, cached in `DATA_DIR/tts/{lib,room}` by hash of voice+text. lib = built-in text, kept for good; room = custom text, swept with saved games. The game prefetches (titles at start, prompts during answering) and only uses clips already on disk when a phase starts (`spokenPhase` stretches the phase to fit), so speech never blocks. Clients can only fetch clips the server made. Answers are read during voting (`answerLines`: all of a matchup's answers or none, not in the emoji round), one card at a time with a `spoken.versus` line between them; `matchup.answerAt` tells the big screen when each card lands (inline `animation-delay`); voting doesn't close before the last answer is read (`readUntil`), even if everyone has voted (the facilitator's Next still skips); each answer's clip is queued the moment it's submitted. The Speech account is a **shared lab resource** in `rg-lab-shared` (`infra/lab/`), key wired in via `listKeys()` into a Container Apps secret. `TTS_FAKE=1` fakes it for tests.
- Language (`settings.lang`, en/sv) drives big screen, phones, prompts, server error messages and the Markdown export; `parsePreviousItems` reads both languages.
- Anonymity works like Quiplash by default: answers are anonymous during voting, then authors and voters are revealed. An optional "Anonymous mode" toggle hides authors, voters and scores entirely.
- Summary exports Markdown (copy / download) so outcomes can go to Jira/Confluence/Slack.
- Min 3 players, max 16. Each player gets 2 prompts per head-to-head round (circular pairing). With 8+ players (`TRIO_MIN_PLAYERS`, setting `trios`, on by default) matchups are three-way: `groupPlayers` in `server/game.ts` makes groups of three plus a pair or two, everyone still in exactly two. Matchups are N-sided arrays everywhere (`tally`/`winnerOf` in `shared/types.ts`).
- Voters can pick "Neither" (`vote` with `choice: null`): stored in `matchup.skips`, counts as done, scores nobody.
- **Drop grace:** a player who goes offline (or everyone, after a server restart) stays in `expectedIds` for `DROP_GRACE_MS` (45 s), so a phone blinking offline doesn't end answering/voting early (bug seen in v0.6). In-memory `droppedAt`; `present(id)`.
- Talk time `NO_TALK` (-1) = "0 s": Sprint results use the Warm-up cooldown, no discussion box.
- Reactions carry `from` (player id, not in anonymous mode); the big screen floats them up from `[data-pid]` (lobby tile, done tile or footer avatar; audience → the "watching" chip).
- Phones can leave from the lobby (`leave`): the player is removed and big screens get `{t:"left", name}` for a toast. The button replaces "Not you?".
- Music (`src/sound.ts`): five synthesised lofi tracks (`TRACKS`), picked by scene (`setMusicScene`: lobby/writing/show/talk/finale, from the host phase); scenes with several tracks rotate every 16 bars; changes land on a bar line. The 🎵 panel shows the track name.
- Kudos are read aloud (`spoken.kudos`): clips queued on submit; at the reveal all-or-none, and the end of the round waits up to 3 s once (`kudosWaited`) for the last clip. `kudosAt` in the host view times each card to its line.
- Prompts per player (`settings.promptsEach`, 0 = auto): one each from `ONE_PROMPT_MIN_PLAYERS` (12); `groupPlayers(ids, trios, each)`.
- Saved games (`server/storage.ts`): write `.tmp`, move the old file to `.bak`, rename. Loading tries file → `.bak` → `.tmp`. The sweeper deletes all three.
- CSS gotcha: `.waiting` is the phone's full-height waiting screen. Don't reuse it as a state class (it made footer avatars tall ovals; they use `pending` now).
- **Extra screens:** `/?screen=ABCD` sends `helloScreen` and gets the host view and reactions, but no control. For hybrid/Teams use (`docs/TEAMS.md`).
- **Rejoin:** phones fall back to the last identity in localStorage when the tab is new (sleeping phones lose tabs), unless another open tab holds that identity's Web Lock (`useIdLock`/`idInUse` in `src/net.ts`; otherwise two desktop tabs became one player and "Leave" in one removed it from under the other; `leave` also sends other sockets on that player `errors.leftElsewhere`), reconnect on `visibilitychange`/`pageshow`, and the server lets a new device take over an *offline* player with the same name and role (`state.aliases`: device id → player id; connection state carries `pid`). Heartbeat is 10 s so dead sockets drop fast.
- **Device id is a secret, player id is public:** player ids are random and made by the server; views (host, screens, kudos form) carry them. The device id (`_pk`) never leaves the phone and server, and a socket finds its player *only* through `state.aliases`. Never fall back to "device id = player id" (before this change anyone could log in as a player with the id from a `?screen=` view and read their check-in mood or kudos). Games saved before this got identity aliases on load.
- **Room creation:** a socket joins a room only with its first message (`decide` in `server/main.ts`). Rooms in memory or saved on disk open for anyone; a *new* room needs a `helloHost`, and one address (the last `X-Forwarded-For` entry behind the ingress) may start `ROOMS_PER_IP` (10) per 10 min. Other sockets get `errors.noRoom` and close code 4404, or `errors.busy` and 4429. At `MAX_ROOMS` the longest-idle room is evicted, since it is saved anyway (`closing` makes the reload wait for that save). Sockets that send nothing for 10 s are closed (4408). `scripts/e2e.mjs` therefore opens the host first and connects everyone else after `hostToken`.
- **Host chatter:** stock spoken lines (`spoken.welcome/write/vote/result/roundDone/poll/lashVote/lashResult/wrap` in i18n) are `optional` speech lines: generated at server start (`warmSpeech`), skipped if not ready. Result reactions are timed with `revealTiming()`, shared with the big screen.
- **Voice effect** (`settings.voiceFx`, in the advanced settings when speech is available): `studio` plate reverb (default, bigger rooms), `radio` (narrow, saturated, retro) or `off`. Web Audio chain in `src/sound.ts` (`VOICE_FX_PRESETS`) between the clip and the voice volume; tune presets with the bench (`node tools/voice-fx/build.mjs`, writes an untracked `voice-fx.html` with live clips embedded).
- **Themes:** `settings.theme` "studio" (default) or "party"; `html[data-theme]`, overrides in `src/studio.css`. Emoji come from Noto Color Emoji (Google Fonts), placed right after the text fonts in `--display`/`--body`, with `"Apple Color Emoji"` before it: Google serves WebKit an OpenType-SVG Noto that Safari/iOS draw as blanks (seen 2026-11-20), so Apple devices use their own emoji.
- The server sends each connection a tailored view (`HostView` / `PlayerView`); never broadcast secret state.
- **Host token:** the first `helloHost` of a room gets `{t:"hostToken"}` (48 hex chars, stored in that browser's localStorage); only its SHA-256 is saved in the game state. Later big screens must present it or get an error. Survives restart. `useRoom` accepts a hello *function* so reconnects send the stored token.
- Missed answers: when exactly one side of a matchup is empty at time-up, `fillMissing` puts a 🆘 quip there (`auto` flag): half vote points, no win bonus, no streak, excluded from highlights. Both empty → matchup skipped.
- End of game: last round → **highlights** (top 3 winning answers, clean sweeps first) → **podium** (shared places via `places()`; the voice says "And the winner is…" then the name(s), timed by `PODIUM_REVEAL`) → summary. Speech lines can carry `at` (ms after the screen appears).
- Usage: `GameRoom` reports start/finish counts to `onUsage`; `server/main.ts` appends them to `DATA_DIR/usage.jsonl` (no names or content); `server/usage.ts` summarises (test games, i.e. with `bot-` device ids or old lines under 8 min, left out), used by `GET /api/stats` (landing page line, cached 60 s) and `npx tsx scripts/usage.ts usage.jsonl [--all]`. Lines carry a random `game` id pairing start and finish, `active` players (who did something), `bots`, `screens`, `vip`.
- Free-tier meter (`server/meter.ts`): `DATA_DIR/meter.json` holds `{ "YYYY-MM": { speechChars, speechClips, runtimeSec, starts } }`. Counts are added to the file about once a minute (read, add, write), so overlapping revisions don't overwrite each other. Speech counts what Azure bills: every character inside `<voice>`, markup like `<prosody>`/`express-as` included (`AzureSpeech.ssml()`). Runtime is process uptime, which is zero while scaled to zero. `/api/stats` has `meter` with each month's share of the limits (`SPEECH_FREE_CHARS` default 500k for F0; `FREE_RUNTIME_HOURS` default 200 = the Container Apps free grant at 0.25 vCPU / 0.5 GiB). The landing page shows it on a second line. The Speech resource is shared with other lab apps and the free grant applies to the whole subscription, so these are Retrolash's own share only.
- **Speech abuse limits** (all fail quiet: a clip that isn't made just means that matchup isn't read aloud, which the all-or-none rule already handles):
  - **Slots:** answers (`room:matchup:player`) and kudos (`room:game:kudos:player`) are prefetched with a slot. A newer line replaces the slot's earlier one if that hasn't started, and waits `SLOT_DELAY_MS` (3 s) for further edits, so spamming resubmissions costs one clip. When answering ends, the bulk prefetch (no slot) releases waiting clips at once.
  - **Per-game budget:** every room clip carries `speechOpts()`, keyed by `room:gameId`, worth `SPEECH_BUDGET_BASE` 6000 + `SPEECH_BUDGET_PER_PLAYER` 3000 × players in billable characters. That's about 3× a real game (bot games use 0.8–2.2k; a 9-player human game is estimated at ~10k). Usage `game` lines carry `speechChars` for tuning.
  - **Monthly guard:** from `SPEECH_STOP_SHARE` (0.85) of the free characters, no new room clips are made for the rest of the month. Stock lines are cached and go on. `meter.speech.paused` in `/api/stats`, and the landing page says so. The markup (cheerful style, +4% rate) is kept on purpose for the better reads.
- State is persisted in room storage; phones keep identity per browser tab (sessionStorage device id passed as PartySocket `id`), and remember the last identity per room in localStorage (12 h) so a closed tab can "Continue as …".

## Dev
- `npm install`, then `npm run dev` (game server :1999 via tsx watch + Vite :5173 on the LAN)
- `node scripts/bots.mjs ABCD 4 [host]` fills a room with bot players (wss for non-local hosts)
- `npm run build` = client to `dist/` + server bundle to `dist-server/main.js`; `npm start` runs it
- `npm run typecheck`; `npm test` = helper self-tests + full end-to-end bot game in Swedish and English (`scripts/e2e.mjs sv|en`, `TIME_SCALE=0.1`; a scripted VIP phone starts the game and presses next), also run in CI
- `node scripts/bots.mjs ABCD 4 [host] [audienceCount]` bots cover every round type, audience, reactions and owner claims
